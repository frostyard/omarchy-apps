# Org-wide decisions (frostyard/core ADRs)

These core ADRs bind `omarchy-apps`. This list records the repository rule that each one applies.

## Decisions this repository follows

- [ADR-0001 — Record architecture decisions](https://github.com/frostyard/core/blob/main/docs/adr/0001-record-architecture-decisions.md): record significant architecture decisions as numbered ADRs under [`docs/adr/`](adr/); reverse an accepted decision with a new ADR.
- [ADR-0002 — Agent-portable instruction surface](https://github.com/frostyard/core/blob/main/docs/adr/0002-agent-portable-instruction-surface.md): keep agent instructions tool-agnostic in [`AGENTS.md`](../AGENTS.md), with tool-specific entry points as symlinks.
- [ADR-0018 — Org-wide agent instruction and knowledge surfaces](https://github.com/frostyard/core/blob/main/docs/adr/0018-org-wide-agent-instruction-and-knowledge-surfaces.md): [`AGENTS.md`](../AGENTS.md) is canonical. The four aliases are relative symlinks to it. Blocking corrections add one record file under `.memory/corrections/` ([`.memory/README.md`](../.memory/README.md)).
- [ADR-0019 — Repository governance as machine-readable policy with risk tiers](https://github.com/frostyard/core/blob/main/docs/adr/0019-governance-as-code-and-risk-tiers.md): [`.github/risk-paths.json`](../.github/risk-paths.json) identifies high-risk package and publication paths. [`.github/pull_request_template.md`](../.github/pull_request_template.md) requires a risk tier.
- [ADR-0020 — Trust boundaries for AI automation in CI](https://github.com/frostyard/core/blob/main/docs/adr/0020-ai-automation-trust-boundaries.md): privileged workflows never check out or execute PR-controlled code; the [`pull_request_target` triage caller](../.github/workflows/risk-paths.yml) runs pinned core code without a checkout.
- [ADR-0021 — SHA-pinned actions and least-privilege CI workflows](https://github.com/frostyard/core/blob/main/docs/adr/0021-sha-pinned-actions-and-least-privilege-ci.md): workflows pin actions to commit SHAs, use least privilege and disable checkout credential persistence.
- [ADR-0023 — External downloads are version-pinned and checksum-verified](https://github.com/frostyard/core/blob/main/docs/adr/0023-verified-pinned-downloads.md): pin upstream artifacts by version, URL and SHA-256 in [`download/checksums.json`](../download/checksums.json), reject mismatches in [`verified-download.sh`](../download/verified-download.sh), and check for updates in [`check-dependencies.yml`](../.github/workflows/check-dependencies.yml).
- [ADR-0025 — One docs/ tree per repository, in core's four-category shape](https://github.com/frostyard/core/blob/main/docs/adr/0025-consolidate-repository-docs-into-docs.md): repository documentation lives in the [`docs/`](README.md) tree and starts from category templates.
- [ADR-0029 — ACMM conformance via canonical aliases](https://github.com/frostyard/core/blob/main/docs/adr/0029-acmm-conformance-via-canonical-aliases.md): `CLAUDE.md`, `GEMINI.md`, `.cursorrules` and `.github/copilot-instructions.md` are relative symlinks to `AGENTS.md`.
- [ADR-0033 — Permit link-only maintenance in immutable ADRs](https://github.com/frostyard/core/blob/main/docs/adr/0033-link-maintenance-in-immutable-adrs.md): edit accepted or superseded ADRs only to repair links without changing their meaning, as the [ADR template](adr/TEMPLATE.md) notes.
- [ADR-0040 — Publish the repository settings contract](https://github.com/frostyard/core/blob/main/docs/adr/0040-publish-the-repository-settings-contract.md): baseline B14 draws on this ADR: [`SECURITY.md`](../SECURITY.md) names GitHub private vulnerability reporting and links the repository's `/security` page. The repository is not enrolled in the settings contract.
- [ADR-0041 — Retire copilot-review-apply where Snowcat gates review](https://github.com/frostyard/core/blob/main/docs/adr/0041-retire-copilot-review-apply-where-snowcat-gates-review.md): do not dispatch the Copilot coding agent against review findings; the issue handoff is separate from PR review.
- [ADR-0043 — Pin repository tools in mise and name the verify gate](https://github.com/frostyard/core/blob/main/docs/adr/0043-pin-repository-tools-in-mise-and-name-the-verify-gate.md): [`mise.toml`](../mise.toml) and [`mise.lock`](../mise.lock) pin the repository tools.
- [ADR-0044 — Expose the make gate triad in every repository](https://github.com/frostyard/core/blob/main/docs/adr/0044-expose-the-make-gate-triad-in-every-repository.md): the [`Makefile`](../Makefile) exposes `verify`, `check` and `ci`.
- [ADR-0051 — ADRs state facts only, not the process that produced them](https://github.com/frostyard/core/blob/main/docs/adr/0051-adrs-state-facts-not-process.md): write ADR context, decisions and consequences as facts, not as a record of who asked or how the decision was reached.
- [ADR-0055 — Publish Debian packages through the apt-publisher single writer](https://github.com/frostyard/core/blob/main/docs/adr/0055-publish-debian-packages-through-the-apt-publisher.md): this repository sends package publication requests to apt-publisher. It does not hold signing or bucket credentials.
- [ADR-0056 — The APT publisher triggers image rebuilds after packages are live](https://github.com/frostyard/core/blob/main/docs/adr/0056-rebuild-images-after-apt-publication.md): [`build.yml`](../.github/workflows/build.yml) sends `publish-deb` to apt-publisher rather than dispatching image builds itself; apt-publisher notifies downstream repositories after publication checks pass.
- [ADR-0059 — Publish image-only packages in a separate APT component](https://github.com/frostyard/core/blob/main/docs/adr/0059-publish-image-only-packages-in-a-separate-apt-component.md): apt-publisher routes these packages to the registered `main` component; the producer does not choose a component in its publication request.
- [ADR-0060 — Publish omarchy-apps through the apt-publisher](https://github.com/frostyard/core/blob/main/docs/adr/0060-publish-omarchy-apps-through-the-apt-publisher.md): omarchy-apps attaches built Debian packages to a release and requests publication.
- [ADR-0066 — Build only the omarchy-apps packages that Snosi uses](https://github.com/frostyard/core/blob/main/docs/adr/0066-build-only-the-omarchy-apps-packages-that-snosi-uses.md): the maintained build set contains only packages used by a snosi image or sysext.
- [ADR-0067 — Publish omarchy-apps packages on change, and keep the newest two](https://github.com/frostyard/core/blob/main/docs/adr/0067-publish-omarchy-apps-on-change-and-keep-the-newest-two.md): publication follows the input digest and apt-publisher keeps the newest two versions of each app.
- [ADR-0068 — Label pull requests that touch high-risk paths](https://github.com/frostyard/core/blob/main/docs/adr/0068-label-pull-requests-that-touch-high-risk-paths.md): [`.github/workflows/risk-paths.yml`](../.github/workflows/risk-paths.yml) applies the level label of the strictest matching entry (`level:L1` to `level:L4`) and `risk:high` at L1 and L2 to matching pull requests (core ADR-0078).
- [ADR-0071 — Hold every code repository to one baseline](https://github.com/frostyard/core/blob/main/docs/adr/0071-hold-every-code-repository-to-one-baseline.md): this repository carries the baseline guard and its negative tests.
- [ADR-0072 — Write every README to one standard](https://github.com/frostyard/core/blob/main/docs/adr/0072-write-every-readme-to-one-standard.md): [the root README](../README.md) is the packaging README for this repository.
- [ADR-0073 — Let CI run the `make ci` targets as separate jobs](https://github.com/frostyard/core/blob/main/docs/adr/0073-let-ci-run-the-make-ci-targets-as-separate-jobs.md): [CI](../.github/workflows/ci.yml) runs `make ci` in one job on pull requests, satisfying baseline B12.
- [ADR-0075 — Group Dependabot updates and sync skills once a day](https://github.com/frostyard/core/blob/main/docs/adr/0075-batch-routine-pull-requests.md): each entry of [`.github/dependabot.yml`](../.github/dependabot.yml) has 1 `patterns: ["*"]` group, so Dependabot opens at most 1 version-update PR for each ecosystem and run; security updates stay 1 PR each.
- [ADR-0076 — Require status checks on every default branch](https://github.com/frostyard/core/blob/main/docs/adr/0076-require-status-checks-on-every-default-branch.md): require status checks on `main` that cover the acceptance gate and can run on every pull request to it. The `ci` check covers the gate; the branch rules separately list app-specific Forky smoke checks.
- [ADR-0077 — Bind `ready-for-human` to the head commit](https://github.com/frostyard/core/blob/main/docs/adr/0077-bind-ready-for-human-to-the-head-commit.md): the [`pull_request_target` triage caller](../.github/workflows/risk-paths.yml) removes `ready-for-human` when the head changes or the label is added before checks at the head are green.
- [ADR-0078 — Sort pull requests by levels L1 to L4](https://github.com/frostyard/core/blob/main/docs/adr/0078-sort-pull-requests-by-levels-l1-to-l4.md): [`.github/risk-paths.json`](../.github/risk-paths.json) defines path levels and an L3 default; triage applies the strictest level after organization floors, never lowers a label, and adds `risk:high` at L1 and L2.
- [ADR-0081 — Store each correction in a file of its own](https://github.com/frostyard/core/blob/main/docs/adr/0081-store-each-correction-in-a-file-of-its-own.md): amends ADR-0018 and ADR-0071 in part. Each correction record is 1 file in [`.memory/corrections/`](../.memory/README.md), in canonical form; a record is never removed or renamed.
- [ADR-0082 — Verify the build provenance of omarchy-apps](https://github.com/frostyard/core/blob/main/docs/adr/0082-verify-the-build-provenance-of-omarchy-apps.md): [`build.yml`](../.github/workflows/build.yml) attests each released `.deb`; apt-publisher verifies provenance from that workflow on `refs/heads/main` on a GitHub-hosted runner before publishing.
- [ADR-0083 — Run the CI gate locally as `make ci`](https://github.com/frostyard/core/blob/main/docs/adr/0083-run-the-ci-gate-locally-as-make-ci.md): `make ci` runs the local lint and test gate that [`ci.yml`](../.github/workflows/ci.yml) uses, and [`AGENTS.md`](../AGENTS.md) names it.
- [ADR-0086 — Let each PR triage caller grant the triage token](https://github.com/frostyard/core/blob/main/docs/adr/0086-let-each-pr-triage-caller-grant-the-triage-token.md): each job that calls core's `pr-triage.yml` grants `contents: read` and `pull-requests: write` at job scope.
- [ADR-0087 — Start PR triage by dispatch for bot pull requests](https://github.com/frostyard/core/blob/main/docs/adr/0087-start-pr-triage-by-dispatch-for-bot-pull-requests.md): the dependency bump workflow dispatches [`pr-triage-dispatch.yml`](../.github/workflows/pr-triage-dispatch.yml) with the bot PR number so triage can apply risk labels.
- [ADR-0088 — Read the action pin in workflow tests, never hard-code it](https://github.com/frostyard/core/blob/main/docs/adr/0088-read-the-action-pin-in-workflow-tests-never-hard-code-it.md): [`tests/check-baseline-test.sh`](../tests/check-baseline-test.sh) reads each pin from the copied workflow.
- [ADR-0089 — Run Dependabot version updates monthly, in 1 entry for each ecosystem](https://github.com/frostyard/core/blob/main/docs/adr/0089-run-dependabot-version-updates-monthly-in-one-entry-per-ecosystem.md): each entry of [`.github/dependabot.yml`](../.github/dependabot.yml) runs `interval: monthly` (the 1st of the month, at a time GitHub picks), and each ecosystem has 1 entry, with a `directories` list when its manifests are in several directories (amends ADR-0071 and ADR-0075 in part); security updates stay immediate.
- [ADR-0090 — Scope action pins and check them repository-wide](https://github.com/frostyard/core/blob/main/docs/adr/0090-scope-action-pins-and-check-them-repository-wide.md): [`tests/check-baseline.sh`](../tests/check-baseline.sh) checks the comment form and 1 SHA per action over `.github/workflows` and `.github/actions`.
- [ADR-0091 — Run no Claude Code action in frostyard workflows](https://github.com/frostyard/core/blob/main/docs/adr/0091-run-no-claude-code-action-in-frostyard-workflows.md): baseline B20 forbids the Claude Code and Claude Code Base actions, including forks or mirrors under the same repository names, in workflows and composite actions at any ref.

## Not applicable

- ADR-0012, ADR-0038 and ADR-0053 concern Go repositories; this repository has no Go module and publishes packages directly from `main`.
- ADR-0026 does not apply because core’s skills sync does not target this repository.
- ADR-0042 does not apply because this repository is not enrolled in the settings contract.
- ADR-0070 and ADR-0084 concern user-facing tools; this repository packages upstream apps and is not a tool with its own user documentation home.
